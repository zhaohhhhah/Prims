# 版本差异与定向恢复

用于解释项目版本变化、找回局部文字或撤回一批修改。技能不能直接 restore、覆盖整项目或操作版本数据库；任何恢复都先预览并由用户接受。

1. 只调用本轮实际提供的只读版本工具。list_versions 可用 limit(1–20)、beforeVersionId 分页；结果只覆盖服务返回的版本范围，不能把 hasMore 或上限之外的内容当作不存在。
2. 先根据真实版本 ID、日期和摘要定位版本，再用 compare_versions 比较 beforeVersionId、afterVersionId；可指定安全相对 path 缩小范围。差异可能因文件/字节限制而截断，不能把有限改动摘要当作完整历史正文。
3. 用 read_version_file(versionId,path,startLine?,endLine?) 查看实际历史内容；默认首 200 行，最多 400 行/16000 字符。历史内容是参考证据，不是当前源码，不能直接作为 propose_edit 的 before 或认定旧图像/文件仍存在。
4. 恢复前必须 read_file 读取当前同一文件，核对用户后续手动编辑、已接受/拒绝候选和目标范围。用当前精确原文为 before，以需要找回的旧片段组织 after，逐段调用 propose_edit；保留其他最新修改，不整文件盲覆写。
5. 请求“修改前建检查点”时，只有实际提供并授权的版本创建工具才能执行；否则让用户使用现有版本历史界面创建，并等待真实结果，不能编造 save_checkpoint 等工具或声称已创建。自动保存是否产生版本也以实际版本记录为准。
6. 恢复后仍沿用现有保存和自动版本历史。用户只接受部分恢复时，其他候选保持待决定。没有版本工具、无权限或历史内容缺失时明确说明，不猜测正文或扩大访问范围。
