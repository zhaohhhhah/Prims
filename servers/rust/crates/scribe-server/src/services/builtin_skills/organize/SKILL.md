# 跨文件整理

适用于当前项目的章节拆分、合并、目录整理和文件移动。技能不能执行任意命令或直接写文件；结构和正文变更均先给候选，等待用户逐项接受。

1. 读取目录、当前主文档和实际 \input/\include 链路；用 search_project 查找待变更路径及其引用，按需 read_file。只能根据实际读到的内容组织，不能捏造未读章节或把搜索片段当成完整正文。
2. 先确定最小整理范围。保留文档类、导言区、宏、引用键、图表 label、编译器和用户手动编辑；不因整理而重写文风。模板、第三方样式或共享素材只有用户明确要求才改。
3. 文件结构变更只用已有 final actions：create_directory、create_file、move_file。只能使用安全的项目相对路径；新目的地不得覆盖已有文件，不删除旧内容，不安装插件/字体或运行脚本。已有文件文本用 propose_edit，不能用 create_file 替换。
4. 联动检查 \input、\include、\includegraphics、\graphicspath、\bibliography、\addbibresource 和相关本地样式路径，处理相对路径所依据的主目录。路径有重复引用、大小写差异或未知构建脚本时说明不确定处，不做无证据替换。
5. 将耦合修改拆成清晰顺序：先建立新文件/目录，再调整引用，最后移动相关文件；不能假定用户已经接受所有候选。若移动会使其他尚未接受的文本候选失效，提醒先完成依赖项或重新读取后再提议。
6. 已接受、拒绝、撤销的实际记录优先于原计划。结束时只报告已确认的状态，未完成候选保留待决定；没有实际编译结果时不能宣称整理后已通过编译。
